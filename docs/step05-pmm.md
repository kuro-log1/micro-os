# Step 05 — 물리 메모리 관리 (PMM, 비트맵)

> GRUB이 알려 준 메모리 지도를 읽어, 4KB 물리 프레임을 빌려 주고(`pmm_alloc_page`) 돌려받는(`pmm_free_page`) 할당기를 만든다.

## 목표

`[pmm] total: N MB  free: M MB` 출력, 해제한 프레임이 다음 할당에서 다시 나온다.

## 이 단계가 만드는 틀

- **`pmm_alloc_page()` / `pmm_free_page()`** — 커널의 모든 메모리는 결국 여기서 나온다.
  페이지 테이블(06), 힙(07), 프로세스 스택, 유저 페이지(14·18), fork 복사본(20)까지
- **"물리 주소를 그대로 포인터로 쓴다"** 는 약속 — Step 01의 1GB 아이덴티티 매핑 덕분. (그래서 QEMU 메모리는 1GB 미만인 512MB로 쓴다)
- **multiboot2 정보 읽는 법** — 태그 목록을 도는 패턴. Step 13의 `mmap_log` 도 같은 방식

## 만들 파일

| 파일 | 역할 |
|---|---|
| `kernel/multiboot2.h` | 태그 헤더, 메모리 맵 태그(type 6), 엔트리 구조체 |
| `mm/pmm.c` | 비트맵(4GB분 = 1M 프레임 = 128KB), `pmm_init` · `pmm_alloc_page` · `pmm_free_page` |
| `kernel/main.c` | `pmm_init(info)` + 할당/해제 실습 |

읽는 순서: `kernel/multiboot2.h` → `mm/pmm.c` (`pmm_init` 의 태그 순회 → alloc/free)

## 핵심 개념

- **메모리 맵**: RAM은 연속이 아니다. BIOS 영역, 장치 메모리(MMIO) 같은 구멍이 있다. GRUB이 `info` 주소에 "어디가 사용 가능(type 1)한지" 목록을 넘겨준다
- **태그 순회**: `info + 8` 부터 태그가 이어지고, 각 태그는 **8바이트 정렬** — 다음 태그 주소는 `(tag + size + 7) & ~7`. type 0이 끝
- **비트맵**: 프레임 하나에 1비트. 여기서는 **1 = 비어 있음**. 할당은 앞에서부터 1인 비트를 찾아 0으로 (선형 탐색, 단순하지만 느림)
- **커널 자신을 지키기**: `_kernel_end`(linker.ld) 아래 프레임은 전부 예약으로 둔다. 비트맵 배열 자체도 커널 BSS에 있으니 함께 보호됨. 1MB 아래(BIOS 영역)도 자연히 제외
- **페이지 경계 맞춤**: 영역 시작은 올림, 끝은 내림 — 일부만 사용 가능한 프레임은 쓰지 않는다

## 직접 만든다면

1. `multiboot2.h` 구조체 정의, 태그를 돌며 type과 크기만 출력
2. 메모리 맵 엔트리(base, length, type) 출력 — QEMU 512MB에서 어떤 영역이 나오는지 관찰
3. 비트맵 + set/clear/test 인라인 함수
4. 사용 가능 영역을 비트맵에 표시 (커널 끝 아래는 제외)
5. alloc/free 구현 후 같은 주소가 재사용되는지 확인

## 확인

- `[pmm] total: ~510 MB  free: ~505 MB` 근처 값
- `[test] alloc a=0x... b=0x...` 다음 줄에서 `alloc again` 이 `a` 와 같은 주소

## 자주 막히는 곳

| 증상 | 원인 |
|---|---|
| total이 0 | 태그 정렬 계산 실수로 메모리 맵 태그를 지나침 |
| 할당한 주소에 쓰자마자 커널이 이상해짐 | 커널 영역을 사용 가능으로 표시함 (`_kernel_end` 검사 누락) |
| 1GB 넘는 주소가 나와 접근 시 Page Fault | 아이덴티티 매핑은 1GB까지 — QEMU `-m` 을 1GB 미만으로 |
