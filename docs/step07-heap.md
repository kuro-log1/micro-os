# Step 07 — 커널 힙 (kmalloc / kfree)

> 가상 12GB 위치에 1MB 영역을 매핑해 두고, 블록 연결 리스트로 원하는 크기만큼 잘라 준다.

## 목표

`kmalloc(100)`, `kmalloc(200)` 이 서로 다른 주소를 주고, 해제하면 블록이 다시 합쳐진다 (`heap_dump` 의 blocks 수 변화).

## 이 단계가 만드는 틀

- **`kmalloc(size)` / `kfree(ptr)`** — 이후 거의 모든 커널 객체가 힙에서 나온다:
  PCB와 커널 스택(08), FS 노드(09), ELF 파일 버퍼(18), fork한 자식 PCB(20)
- **"PMM(물리) → VMM(매핑) → 힙(잘라 쓰기)"** 3층 구조 완성. 메모리 관리의 기본 그림

## 만들 파일

| 파일 | 역할 |
|---|---|
| `mm/heap.c` | `HEAP_BASE = 0x300000000`, 256페이지(1MB) 매핑, `block_t` 헤더, first-fit 할당 · 분할 · 병합 |
| `mm/heap.h` | 선언 |
| `kernel/main.c` | `heap_init` + 할당/해제 실습 |

읽는 순서: `mm/heap.c` (`block_t` → `heap_init` → `kmalloc` → `kfree`)

## 핵심 개념

- **블록 = [헤더 24바이트][데이터]** — 헤더에 `size`(데이터 크기), `used`, `next`. 블록들이 힙 전체를 빈틈없이 덮는다
  ```
  [hdr|used 104B][hdr|used 200B][hdr|free 나머지 .......]
  ```
- **first-fit**: 앞에서부터 "비어 있고 충분히 큰" 첫 블록을 고른다
- **분할**: 고른 블록이 요청보다 `헤더 + 8` 이상 크면 뒤쪽을 새 빈 블록으로 떼어 낸다 (안 그러면 큰 블록 하나를 통째로 낭비)
- **병합**: `kfree` 할 때 **바로 뒤** 블록이 비어 있으면 합친다. 앞쪽과는 합치지 않음(단방향 리스트라 앞 블록을 모름) → 해제 순서에 따라 조각이 남을 수 있다
- **8바이트 정렬**: 모든 크기를 8의 배수로 올려 반환 주소가 항상 정렬되게
- **왜 12GB?** 1GB 아이덴티티 영역과 안 겹치고, Step 12의 유저 영역(16GB~)과도 떨어진 곳

## 직접 만든다면

1. `heap_init`: 256번 `pmm_alloc_page` + `vmm_map_page`, 시작에 빈 블록 하나
2. 분할 없는 `kmalloc` (블록 통째로 주기) → 동작 확인
3. 분할 추가
4. `kfree` + 뒤 블록 병합
5. `heap_dump` 로 블록 목록 확인

## 확인

- 할당 후 `blocks=3`, 해제 후 `blocks=1`
- 생각해 볼 것: `kfree(a)` 다음 `kfree(b)` 로 순서를 바꾸면 결과가 어떻게 다를까? (a는 뒤의 b가 아직 사용 중이라 못 합침 → 2블록)

## 자주 막히는 곳

| 증상 | 원인 |
|---|---|
| 두 번째 kmalloc이 첫 번째와 같은 주소 | 분할 후 `used = 1` 표시 누락 |
| 헤더가 깨져 리스트 순회 중 Page Fault | 할당받은 크기보다 많이 씀 (버퍼 오버플로가 다음 헤더를 덮음) |
| 1MB도 안 썼는데 NULL | 병합이 안 돼 조각만 남음 |
