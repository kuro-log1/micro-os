# Step 04 — PS/2 키보드 (IRQ1) & 마우스 (IRQ12)

> 키가 눌리면 IRQ 핸들러가 글자를 링 버퍼에 넣고, 프로그램은 `keyboard_getchar()` 로 꺼내 간다.

## 목표

타이핑한 글자가 화면에 그대로 찍히고, 마우스를 움직이면 회색 커서 칸이 따라 움직인다.

## 이 단계가 만드는 틀

- **"인터럽트 쪽은 넣기만, 사용하는 쪽은 꺼내기만"** 하는 생산자-소비자 구조 (링 버퍼)
- **`keyboard_getchar()`** — 글자가 올 때까지 `hlt` 로 기다리는 **블로킹 입력 API**. Step 09의 셸이 이 함수 하나로 입력을 받는다
- 드라이버를 붙이는 표준 모양: `xxx_init()` 에서 `irq_install_handler` 로 등록, 핸들러는 짧게

## 만들 파일

| 파일 | 역할 |
|---|---|
| `drivers/keyboard.c` | 스캔코드 세트 1 → ASCII 표, 256칸 링 버퍼(`kb_head` / `kb_tail`), `keyboard_getchar` |
| `drivers/mouse.c` | PS/2 보조 장치 켜기, 3바이트 패킷 조립, VGA 칸 색을 바꿔 커서 표시 |
| `kernel/timer.c` | 초 단위 출력 제거 (타이핑을 방해해서) |
| `kernel/main.c` | `keyboard_init` · `mouse_init`, 글자 에코 루프 |

읽는 순서: `drivers/keyboard.c` → `drivers/mouse.c`

## 핵심 개념

- **스캔코드**: 키보드는 글자가 아니라 "몇 번 키가 눌렸다/떼졌다"를 보낸다. 포트 `0x60` 에서 읽음.
  떼는 신호(break code)는 누름 코드에 `0x80` 을 더한 값 → 무시한다. (Shift 처리는 하지 않음 — 소문자만)
- **링 버퍼**: `head` 는 핸들러가, `tail` 은 소비자가 움직인다. `next == tail` 이면 가득 참 → 버림.
  한 쪽만 쓰는 변수라 단일 코어에서는 락 없이 안전. `volatile` 은 컴파일러가 루프에서 값을 캐시하지 않게
- **`sti; hlt`**: "인터럽트를 켜고 다음 인터럽트까지 잔다". 바쁜 대기(busy wait) 대신 CPU를 쉬게 한다
- **PS/2 마우스**: 컨트롤러(`0x64`)에 보조 장치 활성화(`0xA8`), 설정 바이트에 IRQ12 허용, `0xD4` 를 앞세워 마우스에 명령 전달.
  패킷 3바이트 = [버튼·부호 비트, dx, dy]. 첫 바이트의 bit 3이 항상 1인 걸로 동기화

## 직접 만든다면

1. 핸들러에서 스캔코드를 16진수로 출력해 보기 — 누를 때/뗄 때 값 차이 관찰
2. 스캔코드 → ASCII 표 만들고, 누름만 출력
3. 출력 대신 링 버퍼에 넣고, `keyboard_getchar` 로 꺼내 에코
4. (선택) 마우스: 패킷 3바이트 모으기 → 좌표 갱신 → 커서 칸 색 반전

## 확인

- 글자, 숫자, Enter(줄바꿈), Backspace가 동작
- QEMU 창을 클릭하면 마우스가 잡히고(Ctrl+Alt+G로 풀기) 회색 칸이 움직인다

## 자주 막히는 곳

| 증상 | 원인 |
|---|---|
| 글자가 두 번씩 나옴 | break code(떼기)도 처리하고 있음 |
| 첫 키만 받고 멈춤 | 포트 `0x60` 을 안 읽음 → 컨트롤러가 다음 키를 안 보냄 / EOI 누락 |
| 마우스 커서가 미친 듯이 튐 | 패킷 동기화 실패 (bit 3 확인 없이 아무 바이트부터 모음) |
