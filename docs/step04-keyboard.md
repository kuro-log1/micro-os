# Step 04 — PS/2 키보드 (IRQ1) & 마우스 (IRQ12)

인터럽트를 받을 수 있게 됐으니, 이제 커널이 사람의 입력을 받을 차례입니다. 이번 단계가 끝나면 타이핑한 글자가 화면에 그대로 찍히고, 마우스를 움직이면 회색 칸 하나가 커서처럼 따라다닙니다.
이 단계에서 진짜 중요한 것은 키보드 코드 자체보다 **입력을 주고받는 구조** 입니다. 키보드 인터럽트는 언제 올지 모르고, 글자를 원하는 프로그램은 자기 일정대로 글자를 꺼내 갑니다. 이 둘을 이어 주는 것이 **링 버퍼** 이고, 그 위에 "글자가 올 때까지 기다리는" `keyboard_getchar()` 가 놓입니다. Step 09의 셸은 이 함수 하나로 사용자의 입력을 받습니다.

새 파일은 `drivers/keyboard.c`·`keyboard.h`, `drivers/mouse.c`·`mouse.h` 입니다. `kernel/timer.c` 에서는 1초마다 찍던 출력을 지우고(타이핑한 글자 사이에 끼어들어 방해되기 때문입니다), `kernel/main.c` 는 두 드라이버를 초기화한 뒤 키보드 에코 루프를 돕니다.
`keyboard.c` 를 먼저 읽고, 여유가 있으면 `mouse.c` 를 읽으세요. 마우스는 이후 단계에서 쓰이지 않는 곁가지입니다.

## 키보드는 글자가 아니라 "키 번호"를 보낸다

PS/2 키보드는 키를 누를 때마다 IRQ 1을 일으키고, 키보드 컨트롤러의 데이터 포트 `0x60` 에 1바이트를 남깁니다. 이 바이트는 'a' 같은 글자가 아니라 **스캔코드**, 즉 "몇 번 자리 키가 눌렸다"는 번호입니다. 키보드 배열이 나라마다 다르니, 글자로 바꾸는 일은 운영체제의 몫입니다.
기본으로 쓰이는 스캔코드 세트 1에서는 키를 누를 때(make code)와 뗄 때(break code) 각각 신호가 옵니다. 뗄 때의 코드는 누를 때의 코드에 `0x80` 을 더한 값입니다. 예를 들어 'A' 키는 누르면 `0x1E`, 떼면 `0x9E` 입니다.

`keyboard.c` 는 128칸짜리 표 `sc_ascii` 로 스캔코드를 글자로 바꿉니다. `0x1E` 칸에는 `'a'`, `0x1C`(Enter)에는 `'\n'`, `0x0E`(Backspace)에는 `'\b'` 가 들어 있고, 글자가 없는 키(Shift, Ctrl, F1…)는 0입니다.
핸들러는 이렇게 동작합니다.

```c
static void keyboard_handler(registers_t *r) {
    uint8_t sc = inb(0x60);
    if (sc & 0x80) return;        /* 떼는 신호는 무시 */
    char c = sc_ascii[sc];
    if (!c) return;               /* 글자가 없는 키도 무시 */
    ... 링 버퍼에 c 넣기 ...
}
```

무슨 일이 있어도 포트 `0x60` 을 **읽는다** 는 점이 중요합니다. 키보드 컨트롤러는 그 바이트를 누군가 가져가기 전까지 다음 키를 보내지 않습니다.
이 구현은 Shift를 처리하지 않아서 대문자와 기호를 칠 수 없습니다. Shift 키의 make/break 코드를 보고 상태 변수를 하나 두면 되니, 직접 추가해 보기 좋은 연습 문제입니다.

## 링 버퍼: 인터럽트와 프로그램 사이의 우편함

키보드 핸들러가 받은 글자를 바로 화면에 찍으면 어떨까요? 당장은 동작하지만, 셸처럼 "한 줄을 다 입력받은 다음 처리하는" 프로그램을 만들 수 없습니다. 글자를 원하는 쪽이 원할 때 꺼내 갈 수 있어야 합니다.
그래서 핸들러는 글자를 256칸짜리 원형 배열 `kb_buf` 에 넣기만 하고, 꺼내는 일은 `keyboard_getchar()` 가 합니다.

```c
static volatile char kb_buf[256];
static volatile int  kb_head = 0;   /* 다음에 넣을 자리 — 핸들러만 움직임 */
static volatile int  kb_tail = 0;   /* 다음에 꺼낼 자리 — 소비자만 움직임 */
```

`head == tail` 이면 비어 있는 것이고, `head` 를 한 칸 옮긴 자리가 `tail` 이면 가득 찬 것입니다. 가득 찼을 때 들어온 글자는 버립니다. 배열의 끝에 닿으면 `% 256` 으로 처음으로 돌아가니 "링"입니다.
이 구조에는 락이 없는데도 안전합니다. `head` 는 핸들러만, `tail` 은 소비자만 바꾸기 때문입니다. 한 변수를 두 쪽이 동시에 고치는 일이 없고, CPU가 하나뿐인 이상 문제가 생기지 않습니다. 세 변수 모두 `volatile` 인 이유는, 소비자가 "비어 있으면 기다리는" 루프를 도는 동안 컴파일러가 `kb_head` 를 한 번만 읽고 레지스터에 붙잡아 두는 것을 막기 위해서입니다.

## 기다리는 법: sti; hlt

```c
char keyboard_getchar(void) {
    while (kb_head == kb_tail)
        __asm__ volatile("sti; hlt");
    char c = kb_buf[kb_tail];
    kb_tail = (kb_tail + 1) % KB_BUF_SIZE;
    return c;
}
```

버퍼가 비어 있으면 글자가 올 때까지 기다려야 합니다. 빈 루프를 계속 돌면(바쁜 대기) CPU를 100% 쓰면서 아무 일도 하지 않게 됩니다. 대신 `sti; hlt` 로 "인터럽트를 켜고, 다음 인터럽트가 올 때까지 잔다"를 반복합니다. 키보드든 타이머든 인터럽트가 오면 깨어나서 버퍼를 다시 확인합니다.
`sti` 와 `hlt` 를 붙여 쓰는 데에는 이유가 있습니다. x86은 `sti` 바로 다음 한 명령까지는 인터럽트를 받지 않도록 되어 있어서, "인터럽트를 켠 직후, 잠들기 직전"에 인터럽트가 와서 깨울 기회를 놓치는 일이 생기지 않습니다.
이처럼 결과가 올 때까지 호출한 쪽을 붙잡아 두는 함수를 **블로킹** 함수라고 합니다. `keyboard_getchar()` 는 이 커널의 첫 블로킹 입력 함수이고, Step 08 이후에는 이 `hlt` 동안 타이머가 다른 프로세스로 CPU를 넘겨주게 됩니다.

## 마우스: 같은 컨트롤러, 다른 IRQ

PS/2 마우스는 키보드와 같은 컨트롤러(포트 `0x60`, `0x64`)의 두 번째 장치(aux)로 붙어 있고, IRQ 12를 씁니다. 키보드와 달리 기본으로 꺼져 있어서 켜는 과정이 조금 깁니다.
`mouse_init()` 은 컨트롤러 명령 포트 `0x64` 에 `0xA8` 을 보내 aux 장치를 켜고, 설정 바이트를 읽어(`0x20`) IRQ 12 허용 비트를 켜서 다시 씁니다(`0x60`). 그다음 마우스 자체에 명령을 보내 데이터 전송을 시작시킵니다. 컨트롤러에 `0xD4` 를 먼저 보내면 "다음 바이트는 키보드가 아니라 마우스에게 전달하라"는 뜻이 됩니다.

마우스는 움직일 때마다 3바이트 **패킷** 을 보냅니다. 첫 바이트는 버튼 상태와 부호 비트, 둘째는 x 이동량, 셋째는 y 이동량입니다. 인터럽트는 바이트마다 한 번씩 오므로, 핸들러는 바이트를 모았다가 셋이 모이면 처리합니다.
여기서 함정은 **동기화** 입니다. 중간에 한 바이트라도 놓치면 그 뒤로 모든 패킷이 한 칸씩 어긋나 커서가 미친 듯이 튑니다. 다행히 첫 바이트의 bit 3은 항상 1이라서, 패킷의 첫 자리에 bit 3이 0인 바이트가 오면 버리는 방식으로 경계를 다시 맞춥니다.
커서는 Step 01-4에서 미리 만들어 둔 `vga_get_color_at`/`vga_set_color_at` 으로 그립니다. 커서가 있는 칸의 원래 색을 저장해 두고 회색 바탕(`0x70`)으로 바꿨다가, 움직이면 원래 색으로 되돌리고 새 칸을 칠합니다. 글자는 건드리지 않으니 화면 내용이 지워지지 않습니다. PS/2의 y축은 위쪽이 양수라서, 화면 좌표로 바꿀 때 부호를 뒤집습니다.

## 이 단계가 뒤에 남기는 것

"인터럽트 쪽은 넣기만, 사용하는 쪽은 꺼내기만" 하는 생산자-소비자 구조가 생겼습니다. 장치 드라이버를 만들 때 반복해서 쓰게 될 기본 모양입니다.
`keyboard_getchar()` 는 Step 09의 셸, 그리고 Step 19 이후 유저 프로그램의 표준 입력(fd 0)이 기대는 입력 함수입니다.
드라이버를 붙이는 방식도 정형화됐습니다. `xxx_init()` 에서 `irq_install_handler` 로 핸들러를 등록하고, 핸들러는 장치에서 데이터를 꺼내 어딘가에 넣는 일만 짧게 하고 끝냅니다.

## 직접 만들어 보기

처음에는 키보드 핸들러에서 스캔코드를 16진수로 출력만 해 보세요. 키를 누를 때와 뗄 때 값이 어떻게 다른지, Shift나 방향키는 어떤 값을 보내는지 관찰하면 표를 만들 때 큰 도움이 됩니다. 방향키 같은 일부 키는 `0xE0` 을 앞세운 두 바이트를 보낸다는 것도 보일 것입니다.
그다음 표로 글자를 바꿔 누를 때만 출력하고, 출력 대신 링 버퍼에 넣은 뒤 `keyboard_getchar` 로 꺼내 에코하는 구조로 바꿉니다.
마우스는 선택입니다. 해 본다면 패킷 세 바이트를 16진수로 출력해 동기화가 맞는지부터 확인하세요.

## 확인하기

부팅 메시지 뒤에 키보드로 타이핑하면 글자가 그대로 나옵니다. Enter는 줄바꿈, Backspace는 한 칸 지우기로 동작합니다.
QEMU 창을 클릭하면 마우스가 QEMU에 잡히고, 움직이면 화면 가운데의 회색 칸이 따라 움직입니다. `Ctrl+Alt+G` 로 마우스를 풀 수 있습니다.

## 막혔을 때

글자가 두 번씩 찍힌다면 떼는 신호(`sc & 0x80`)를 걸러 내지 않은 것입니다.
첫 키만 받고 더 이상 반응이 없다면 핸들러에서 포트 `0x60` 을 읽지 않았거나, EOI가 빠진 것입니다.
키보드는 되는데 마우스를 움직이자 키보드가 멈춘다면 마우스 핸들러가 EOI를 받지 못하는 경우입니다. IRQ 12는 슬레이브 PIC를 거치므로 두 PIC 모두에 EOI를 보내야 합니다. Step 03의 `pic_send_eoi` 가 이를 처리하는지 확인하세요.
커서가 화면 곳곳으로 튀어 다닌다면 패킷 동기화가 깨진 것입니다. bit 3 검사를 확인하세요.
