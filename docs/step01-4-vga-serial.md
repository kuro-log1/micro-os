# Step 01-4 — VGA · 시리얼 드라이버

64비트 C 코드가 돌기 시작했으니, 이제부터는 어셈블리가 아니라 C로 커널을 키워 갑니다. 그 첫 번째 일은 글자를 편하게 찍는 것입니다.
앞 단계의 `kernel_main` 은 칸 번호를 직접 계산해 VGA 메모리에 썼습니다. 이래서는 줄바꿈도 할 수 없고, 화면이 꽉 차면 어떻게 될지도 알 수 없습니다.
이번 단계에서는 커서 위치를 기억하며 글자를 이어 쓰는 **VGA 드라이버** 와, 같은 글자를 직렬 포트로 내보내 QEMU를 띄운 터미널에 출력하는 **시리얼 드라이버** 를 만듭니다.
그리고 32비트 시절의 `OK` 출력은 이제 지웁니다. 64비트 진입이 확인됐으니 더는 필요 없고, 이제 화면은 드라이버가 관리합니다.

새로 생기는 파일은 `drivers/vga.c`·`vga.h`, `drivers/serial.c`·`serial.h`, `kernel/io.h`, `lib/string.c`·`string.h` 이고, `kernel/main.c` 와 `boot/boot.s` 가 바뀝니다.
`drivers/vga.c` → `kernel/io.h` → `drivers/serial.c` → `lib/string.c` → `kernel/main.c` 순서로 읽기를 권합니다.

## VGA 드라이버: 커서를 기억하는 화면

VGA 텍스트 모드가 `0xB8000` 의 80×25칸이라는 것은 Step 01-2에서 봤습니다. 드라이버가 더하는 것은 "지금 몇 번째 줄 몇 번째 칸에 쓸 차례인가"를 기억하는 두 변수 `row`, `col` 과, 그것을 움직이는 규칙입니다.

`vga_putchar(c)` 는 글자 하나를 받아 경우를 나눕니다. 보통 글자라면 `row * 80 + col` 칸에 `(색 << 8) | 글자` 를 쓰고 `col` 을 하나 늘립니다. `col` 이 80에 닿으면 다음 줄 처음으로 넘어갑니다.
`'\n'` 이면 글자를 쓰지 않고 다음 줄 처음으로, `'\r'` 이면 같은 줄 처음으로 갑니다. `'\b'`(백스페이스)는 한 칸 뒤로 가서 그 칸을 공백으로 지웁니다. 줄의 맨 앞에서 백스페이스를 누르면 윗줄 끝으로 올라갑니다. 이 동작은 지금은 쓰이지 않지만 Step 09의 셸에서 사용자가 입력을 지울 때 그대로 쓰입니다.

줄이 25줄을 넘어가면 `scroll()` 이 불립니다. 2번째 줄부터 마지막 줄까지를 한 줄씩 위로 복사하고, 맨 아래 줄을 공백으로 채운 뒤 커서를 마지막 줄에 둡니다. 화면 메모리를 한 줄 위로 밀어 올리는 것뿐인데, 터미널이 스크롤되는 것처럼 보입니다.
`vga_init()` 은 화면 전체를 공백으로 채우고 커서를 왼쪽 위로 돌립니다. GRUB이 남긴 글자가 이 시점에 사라집니다.

`vga_get_color_at` 과 `vga_set_color_at` 이라는 두 함수도 미리 들어 있습니다. 특정 칸의 색 바이트만 읽고 쓰는 함수로, 지금은 아무도 쓰지 않습니다. Step 04에서 마우스 커서를 그릴 때, 글자는 그대로 두고 그 칸의 색만 뒤집는 데 쓰입니다.

## 포트 I/O: 메모리가 아닌 하드웨어와 이야기하기

VGA 화면은 메모리 주소로 보이지만, 대부분의 오래된 PC 장치는 **I/O 포트** 라는 별도의 주소 공간으로 대화합니다. 포트 번호는 0~65535이고, 일반 `mov` 가 아니라 `in`, `out` 이라는 전용 명령으로만 읽고 쓸 수 있습니다.
C에는 이 명령에 대응하는 문법이 없으므로, 인라인 어셈블리로 감싼 작은 함수를 만듭니다. 그게 `kernel/io.h` 입니다.

```c
static inline void outb(uint16_t port, uint8_t val) {
    __asm__ volatile("outb %0, %1" : : "a"(val), "Nd"(port));
}
static inline uint8_t inb(uint16_t port) {
    uint8_t ret;
    __asm__ volatile("inb %1, %0" : "=a"(ret) : "Nd"(port));
    return ret;
}
```

`"a"` 는 값을 `al` 레지스터에 넣으라는 제약이고, `"Nd"` 는 포트 번호를 0~255 상수로 직접 쓰거나 `dx` 레지스터에 넣으라는 제약입니다. `out` 명령이 정확히 이 두 형태만 허용하기 때문입니다.
`io_wait()` 는 사용하지 않는 포트 `0x80` 에 아무 값이나 써서 아주 짧게 시간을 끄는 함수입니다. Step 03에서 PIC를 설정할 때, 오래된 하드웨어가 명령 사이에 숨 돌릴 틈이 필요해서 씁니다.
이 헤더는 앞으로 장치 드라이버가 생길 때마다 쓰입니다. Step 15에서는 32비트 포트 함수(`outl`/`inl`)가, Step 16에서는 16비트 포트 함수(`outw`/`inw`)가 여기에 추가됩니다.
참고로 지금 코드의 `serial.c` 는 `io.h` 를 포함하지 않고 같은 두 함수를 파일 안에 따로 정의하고 있습니다. 동작에는 차이가 없고, 원래 코드가 그렇게 쓰여 있어서 그대로 둔 것입니다.

## 시리얼 드라이버: 터미널로 보내는 로그

PC의 첫 번째 직렬 포트 COM1은 포트 `0x3F8` 부터 8개의 레지스터를 씁니다. QEMU를 `-serial stdio` 로 띄우면, 이 포트로 보낸 바이트가 QEMU를 실행한 터미널에 그대로 찍힙니다.
이게 왜 중요한지는 커널이 커질수록 실감하게 됩니다. VGA 화면은 25줄뿐이라 금방 스크롤되어 사라지고, 커널이 예외로 죽으면 화면이 멈추거나 지워집니다. 시리얼로 보낸 로그는 터미널에 남아서 스크롤해 다시 볼 수 있고, 파일로 저장할 수도 있습니다. 이후 단계들의 디버깅은 거의 다 시리얼 로그로 합니다.

`serial_init()` 은 직렬 포트를 115200bps, 8비트 데이터, 패리티 없음, 정지 비트 1로 설정합니다.

```c
outb(COM1 + 1, 0x00);  /* 인터럽트 비활성화 */
outb(COM1 + 3, 0x80);  /* DLAB 켜기: 0, 1번 레지스터가 속도 설정용으로 바뀜 */
outb(COM1 + 0, 0x01);  /* 분주값 하위 = 1 → 115200 / 1 = 115200bps */
outb(COM1 + 1, 0x00);  /* 분주값 상위 */
outb(COM1 + 3, 0x03);  /* DLAB 끄기, 8N1 */
outb(COM1 + 2, 0xC7);  /* FIFO 켜기 */
outb(COM1 + 4, 0x0B);  /* RTS, DTR 켜기 */
```

여기서 재미있는 부분은 DLAB 비트입니다. 직렬 포트 칩(UART)은 레지스터 수를 아끼려고, 3번 레지스터의 최상위 비트가 켜져 있을 때 0번과 1번 레지스터를 "데이터/인터럽트 설정"이 아니라 "속도 분주값"으로 쓰게 만들어 두었습니다. 그래서 DLAB을 켜고, 분주값을 쓰고, 다시 끄는 순서가 됩니다.
`serial_putchar(c)` 는 5번 레지스터(Line Status)의 bit 5가 "송신 버퍼 비었음"이 될 때까지 기다렸다가 0번 레지스터에 글자를 씁니다. 실제 하드웨어에서는 115200bps가 CPU에 비해 매우 느리기 때문에, 이 대기가 없으면 앞 글자를 다 보내기 전에 다음 글자가 덮어써집니다.

## 최소한의 문자열 함수

`lib/string.c` 에는 `memset`, `memcpy`, `strlen`, `strcmp` 네 개가 들어 있습니다. 우리 커널에는 C 표준 라이브러리가 없으니, 필요한 함수는 직접 만들어야 합니다.
당장 `kernel_main` 이 이 함수들을 부르지는 않지만, 미리 두는 이유가 있습니다. gcc는 `-ffreestanding` 이라도 큰 구조체를 초기화하거나 복사하는 코드를 만들 때 `memset`, `memcpy` 호출을 스스로 끼워 넣을 수 있습니다. 그런 일이 생기면 링크 단계에서 "undefined reference to memset" 이 납니다. 이 네 함수는 커널이 존재한다고 가정해도 되는 최소한의 바닥입니다.
뒤 단계에서 이 파일에는 `memcmp`(Step 17) 등이 하나씩 덧붙습니다.

## 화면과 시리얼에 동시에 쓰기

`kernel_main` 은 이제 이렇게 생겼습니다.

```c
static void puts_both(const char *s) {
    for (; *s; s++) {
        vga_putchar(*s);
        serial_putchar(*s);
    }
}

void kernel_main(uint64_t magic, uint64_t info) {
    vga_init();
    serial_init();
    puts_both("vga + serial ready\n");
    puts_both("line 2: newline works\n");
    for (;;) __asm__ volatile("hlt");
}
```

`puts_both` 는 다음 단계의 `printf` 가 생기기 전까지 쓰는 임시 함수입니다. 글자 하나를 두 장치에 똑같이 보내는 이 모양이, 다음 단계 `printf` 안의 `emit()` 함수로 그대로 옮겨 갑니다.
초기화 순서도 눈여겨보세요. 출력 장치를 가장 먼저 초기화합니다. 이후 단계에서 어떤 초기화가 실패하든, 그 사실을 알리려면 출력이 먼저 살아 있어야 하기 때문입니다. 최종 코드에서도 `vga_init()` 과 `serial_init()` 은 `kernel_main` 의 맨 첫 두 줄입니다.

`boot.s` 에서는 32비트 `OK` 를 찍던 `movl` 한 줄이 빠집니다. 이것으로 `boot.s` 는 완성된 형태가 되고, Step 10에서 GDT에 칸을 덧붙일 때까지 바뀌지 않습니다.

## 이 단계가 뒤에 남기는 것

`vga_putchar`, `serial_putchar` 는 이후 모든 출력의 최하층입니다. `printf`(Step 01-5), `klog`/`kprintf`(Step 13), 시스템 콜 `write`(Step 14)가 결국 이 두 함수를 부릅니다.
"사용자에게 보여 줄 것은 화면에, 기록으로 남길 것은 시리얼에"라는 구분도 여기서 시작됩니다. Step 13에서 시리얼에만 쓰는 `kprintf` 가 생기면 이 구분이 명확해집니다.
포트 I/O 헬퍼 `io.h` 는 PIC, PIT, 키보드, 마우스, PCI, ATA 드라이버가 전부 쓰는 공용 도구가 됩니다.

## 직접 만들어 보기

먼저 `vga_putchar` 를 보통 글자만 처리하도록 짧게 만들어, `kernel_main` 에서 한 글자씩 불러 보세요. 그다음 `'\n'` 처리, 80칸 넘김 처리를 차례로 넣습니다.
스크롤은 일부러 30줄을 출력하는 루프로 시험해 보면 좋습니다. `scroll()` 없이 돌리면 25줄을 넘는 순간 화면 메모리 바깥(`0xB8FA0` 이후)에 쓰게 되는데, 그 주소에도 메모리가 매핑되어 있어 아무 오류 없이 글자만 사라집니다. 경계 검사가 왜 필요한지 보여 주는 좋은 예입니다.
시리얼은 `serial_init` 없이 `serial_putchar` 만 불러 보고, 터미널에 무엇이 찍히는지 비교해 보세요. QEMU는 설정이 없어도 관대하게 출력해 주는 경우가 많지만, 실제 하드웨어에서는 속도 설정이 맞지 않으면 깨진 글자가 나옵니다.

## 확인하기

화면이 깨끗이 지워진 뒤 왼쪽 위에 두 줄이 나옵니다.

```
vga + serial ready
line 2: newline works
```

같은 두 줄이 QEMU를 실행한 터미널에도 찍혀야 합니다. 화면에만 나오고 터미널에 없다면 QEMU 명령에 `-serial stdio` 가 빠지지 않았는지 확인하세요.

## 막혔을 때

화면에 아무것도 안 나온다면 `vga_init` 이 화면을 지운 뒤 글자를 쓰지 못한 것입니다. `vga` 포인터가 `0xB8000` 인지, 글자와 색을 `(color << 8) | c` 순서로 조합했는지 보세요.
글자가 줄바꿈 없이 한 줄에 이어지면 `'\n'` 분기에서 `row++` 를 빠뜨린 것입니다.
링크 단계에서 `undefined reference to memset` 이나 `memcpy` 가 나오면 `lib/string.c` 가 빌드에 포함됐는지(`lib` 폴더가 Makefile 검색 목록에 있는지) 확인하세요.
터미널 출력이 한 글자씩 빠진다면 `serial_putchar` 의 대기 루프가 없거나, Line Status 레지스터를 `COM1 + 5` 가 아닌 다른 포트에서 읽고 있는 경우입니다.
