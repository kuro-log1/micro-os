# Step 01-5 — 작은 printf (Step 01 완성)

Step 01의 마지막 조각은 `printf` 입니다. 커널을 만드는 동안 가장 많이 하게 될 일은 "이 값이 지금 무엇인가"를 확인하는 것입니다. 페이지 테이블 엔트리, 할당받은 주소, 레지스터 값, 프로세스 번호처럼 대부분 숫자이고, 특히 16진수입니다.
앞 단계의 `puts_both` 로는 문자열만 찍을 수 있었습니다. 이번 단계에서는 C 표준의 `printf` 와 비슷하게 쓰는, 하지만 커널에 꼭 필요한 기능만 담은 100줄짜리 `printf` 를 만듭니다.
이 단계가 끝나면 Step 01 전체가 완성됩니다. GRUB에서 출발해 64비트 C 코드에서 화면과 시리얼에 `micro-os booted!` 를 찍는 커널입니다.

새로 생기는 파일은 `lib/printf.c`·`printf.h` 이고, `kernel/main.c` 가 `printf` 를 쓰도록 바뀝니다.

## 가변 인자 다루기

`printf("%d개, 주소 %p\n", n, ptr)` 처럼 인자 개수가 정해지지 않은 함수는 C의 `<stdarg.h>` 로 만듭니다.
표준 라이브러리가 없는데 헤더를 써도 되냐고 생각할 수 있지만, `<stdarg.h>`, `<stdint.h>`, `<stddef.h>` 는 라이브러리가 아니라 **컴파일러가 제공하는 헤더** 입니다. 함수 구현이 필요 없는 타입 정의와 매크로라서 `-ffreestanding` 환경에서도 그대로 쓸 수 있습니다.

```c
void printf(const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);
    ...  va_arg(ap, int) ...
    va_end(ap);
}
```

`va_start` 로 마지막 고정 인자 다음부터 읽을 준비를 하고, `va_arg(ap, 타입)` 으로 다음 인자를 그 타입으로 하나씩 꺼냅니다. 꺼내는 타입이 실제로 넘긴 타입과 다르면 값이 깨지기 때문에, 형식 문자열이 그 타입을 알려 주는 역할을 합니다.

## 형식 문자열 해석

`printf` 의 본체는 형식 문자열을 한 글자씩 훑는 루프입니다. `%` 가 아니면 그대로 출력하고, `%` 를 만나면 다음 글자를 보고 인자를 하나 꺼내 변환합니다.
지원하는 것은 `%c`(글자), `%s`(문자열), `%d`(부호 있는 10진수), `%u`(부호 없는 10진수), `%x`(16진수), `%p`(포인터), `%%`(퍼센트 기호 자체)입니다. 숫자 변환 앞에 `l` 을 붙이면(`%lu`, `%lx`) 64비트 값을 꺼냅니다.
`l` 이 따로 필요한 이유는 x86-64에서 `int` 는 여전히 32비트이기 때문입니다. 64비트 주소나 크기를 `%x` 로 찍으면 하위 32비트만 나오므로, 64비트 값은 꼭 `%lx` 로 찍어야 합니다. 이 실수는 커널 개발 내내 자주 하게 되니 지금 기억해 두세요.
`%p` 는 항상 `0x` 뒤에 16자리로 0을 채워 출력합니다. 64비트 주소의 자릿수가 들쭉날쭉하면 로그를 눈으로 비교하기 어렵기 때문입니다.
모르는 형식이 오면 `%` 와 그 글자를 그대로 출력합니다. 형식 문자열을 잘못 썼을 때 조용히 사라지는 것보다 눈에 띄는 편이 낫습니다.

## 숫자를 글자로 바꾸기

숫자 출력의 핵심은 `emit_uint(n, base, width)` 하나입니다.

```c
while (n > 0) {
    buf[i++] = digits[n % base];
    n /= base;
}
while (i < width) buf[i++] = '0';   /* 왼쪽 0 채우기 */
while (i-- > 0) emit(buf[i]);       /* 역순 출력 */
```

`n` 을 진법으로 나눈 나머지가 가장 낮은 자릿수이므로, 나머지를 버퍼에 쌓아 가면 숫자가 거꾸로 쌓입니다. 그래서 출력할 때 버퍼를 뒤에서부터 읽습니다. `n` 이 0이면 루프가 한 번도 돌지 않으므로 `'0'` 을 따로 넣어 줍니다.
`digits` 표가 `"0123456789abcdef"` 라서 같은 함수가 10진수와 16진수를 모두 처리합니다.
부호 있는 수는 `emit_int` 가 음수일 때 `'-'` 를 먼저 찍고 절댓값을 `emit_uint` 에 넘깁니다.

## 모든 출력은 emit 한 곳으로

```c
static void emit(char c) {
    vga_putchar(c);
    serial_putchar(c);
}
```

`printf` 가 만들어 내는 글자는 전부 `emit` 을 지나갑니다. 앞 단계의 `puts_both` 가 그대로 여기로 옮겨 온 셈입니다.
출력 대상이 한 함수에 모여 있다는 사실은 나중에 중요해집니다. Step 13에서는 포맷 해석 부분을 `do_printf(emit_fn, ...)` 로 떼어 내고, 출력 함수만 갈아 끼워 "화면+시리얼"용 `printf`, "시리얼 전용" `kprintf`, "타임스탬프를 붙이는" `klog` 를 만들어 냅니다. 이 구조가 가능한 것이 이 단계에서 출력을 한 곳으로 모아 두었기 때문입니다.

## 완성된 kernel_main

```c
void kernel_main(uint64_t magic, uint64_t info) {
    (void)magic;
    (void)info;

    vga_init();
    serial_init();

    printf("============================\n");
    printf("  micro-os booted!\n");
    printf("============================\n");

    for (;;) __asm__ volatile("hlt");
}
```

`(void)magic;` 은 "이 인자를 일부러 쓰지 않는다"는 표시로, `-Wextra` 의 미사용 인자 경고를 막습니다. `info` 는 Step 05에서 메모리 맵을 읽을 때 처음으로 쓰입니다.
마지막의 `hlt` 무한 루프는 커널이 할 일이 없을 때 CPU를 쉬게 하는 자리입니다. Step 03에서 인터럽트가 켜지면 이 `hlt` 는 타이머가 울릴 때마다 잠깐 깨어났다가 다시 잠들게 되고, Step 08에서는 이 흐름 자체가 "idle 프로세스"가 됩니다.

## Step 01 전체를 돌아보며

다섯 개의 작은 단계를 거치며 만든 것을 다시 정리해 보면, 커널이 서 있는 바닥이 어떻게 생겼는지 보입니다.
01-1에서 커널은 1MB에 놓이고 GRUB이 알아보는 형식을 갖췄습니다. 01-2에서 GRUB이 준 메모리 정보 주소를 보관하고 스택을 만들었습니다. 01-3에서 0~1GB 아이덴티티 매핑과 64비트 GDT를 깔고 롱 모드로 넘어가 C 함수를 불렀습니다. 01-4에서 화면과 시리얼 드라이버, 포트 I/O 도구가 생겼고, 01-5에서 숫자까지 찍을 수 있는 `printf` 가 생겼습니다.
앞으로의 단계는 이 바닥 위에 무언가를 하나씩 덧붙여 갑니다. 그리고 이 바닥에서 정한 약속들, 즉 1MB 시작 주소와 `_kernel_end`, 1GB 아이덴티티 매핑, `0x08`/`0x10` 셀렉터, `kernel_main` 의 초기화 순서, `printf` 의 출력 경로는 끝까지 바뀌지 않습니다.

## 직접 만들어 보기

`%s` 와 `%c` 만 지원하는 `printf` 부터 시작해 보세요. 문자열만 찍던 `puts_both` 와 다를 게 없지만 가변 인자 처리를 익힐 수 있습니다.
다음으로 `emit_uint` 를 만들어 `%u` 와 `%x` 를 붙이고, `printf("%x\n", 0xB8000)` 처럼 아는 값을 찍어 확인합니다. 0을 넘겼을 때 아무것도 안 찍히는 실수가 흔하니 `printf("%d\n", 0)` 도 꼭 시험하세요.
`%d` 에서 음수를 처리하고, `l` 접두사와 `%p` 를 마지막에 붙입니다. `printf("%p\n", (void *)kernel_main)` 으로 함수 주소를 찍어 보면 `0x00000000001000..` 처럼 1MB 근처가 나와서, 링커 스크립트의 `. = 1M` 이 실제로 적용됐다는 것도 확인할 수 있습니다.

## 막혔을 때

64비트 값이 이상하게 잘려서 나온다면 `%x` 대신 `%lx` 를 써야 하는 경우입니다. 반대로 32비트 `int` 를 `%lx` 로 찍으면 상위에 쓰레기 값이 붙어 나올 수 있습니다.
`%d` 로 `INT_MIN` 같은 가장 작은 음수를 찍으면 `-n` 계산에서 넘침이 생길 수 있습니다. 이 구현은 64비트로 넓혀서 처리하므로 32비트 범위에서는 문제가 없지만, 직접 만들 때는 주의하세요.
링크 단계에서 `printf` 가 중복 정의됐다는 오류가 나면, 호스트 gcc가 표준 라이브러리를 끌어들인 것입니다. 링커를 `ld` 로 직접 부르고 `--nostdlib` 가 들어갔는지 확인하세요.
