# Step 09 — 셸 & 인메모리 파일시스템

여러 실행 흐름을 돌릴 수 있게 됐으니, 그중 하나를 쓸모 있는 일에 써 봅시다. 앞 단계의 `thread_a` 와 `thread_b` 는 글자만 찍는 시험용이었습니다. 이번에는 그 자리에 **셸** 을 띄웁니다.
셸은 `> ` 프롬프트를 띄우고, 사용자가 입력한 한 줄을 읽어 명령과 인자로 나누고, 명령에 맞는 일을 하는 프로그램입니다. 이것이 생기면 커널은 처음으로 "사람이 조작할 수 있는" 시스템이 됩니다.
셸이 다룰 대상으로, 메모리 위에만 존재하는 아주 간단한 파일시스템도 함께 만듭니다. `mkdir`, `cd`, `ls`, `pwd` 같은 명령이 이 트리를 다룹니다. 재부팅하면 사라지는 장난감이지만, "파일시스템은 어떤 연산을 제공해야 하는가"를 처음으로 생각해 보게 해 줍니다.
이 단계로 Part 1이 끝납니다. 부팅해서, 인터럽트를 받고, 메모리를 관리하고, 여러 흐름을 번갈아 돌리며, 사람과 대화하는 커널이 완성됩니다. 이 단계의 코드는 원래 저장소의 커밋 `bfc5002` 와 같습니다.

새 파일은 `fs/fs.c`·`fs.h` 와 `shell/shell.c`·`shell.h` 이고, `kernel/main.c` 는 테스트 스레드 대신 셸 프로세스를 등록합니다.
`fs/fs.c` → `shell/shell.c` → `kernel/main.c` 순서로 읽으세요.

## 셸도 그냥 프로세스다

`kernel_main` 의 끝은 앞 단계와 거의 같습니다. 다만 등록하는 프로세스가 `thread_a`, `thread_b` 대신 `shell_run` 하나입니다.

```c
process_t *idle = process_create_idle();
scheduler_init(idle);
scheduler_add(process_create(shell_run));
schedule();
```

이제 시스템에는 프로세스가 둘 있습니다. idle(pid 0)은 `sti; hlt` 루프를 돌고, 셸(pid 1)은 대부분의 시간을 `keyboard_getchar()` 안의 `sti; hlt` 에서 보냅니다. 타이머가 100ms마다 둘 사이를 오가지만, 둘 다 거의 잠들어 있으니 CPU는 대부분 쉬고 있습니다.
셸이 커널 안의 특별한 코드가 아니라 스케줄러가 돌리는 프로세스 하나라는 점이 중요합니다. 이 구조 덕분에 Step 14 이후에는 셸이 키보드를 기다리는 동안 유저 프로그램이 동시에 돌 수 있습니다.

## readline: 한 줄 읽기

```c
static void readline(char *buf) {
    int i = 0;
    while (1) {
        char c = keyboard_getchar();
        if (c == '\n')      { buf[i] = '\0'; printf("\n"); return; }
        else if (c == '\b') { if (i > 0) { i--; printf("\b \b"); } }
        else if (i < LINE_MAX - 1) { buf[i++] = c; printf("%c", c); }
    }
}
```

`readline` 은 Enter가 올 때까지 글자를 버퍼에 모읍니다. 우리가 평소 쓰는 터미널은 운영체제와 터미널 프로그램이 입력한 글자를 화면에 보여 주는 일(에코)을 대신 해 주지만, 여기서는 그런 계층이 없으니 셸이 받은 글자를 직접 화면에 찍습니다.
백스페이스 처리는 버퍼에서 한 글자를 빼고 화면에 `"\b \b"` 를 출력하는 것입니다. 커서를 한 칸 뒤로 옮기고(`\b`), 공백으로 그 글자를 덮고(` `), 다시 한 칸 뒤로 옮깁니다(`\b`). Step 01-4의 `vga_putchar` 가 `\b` 를 이미 처리하도록 만들어 두었기 때문에 가능한 일입니다.
`i > 0` 검사가 없으면 버퍼가 비었을 때 백스페이스를 누르면 `i` 가 음수가 되고, 화면에서는 프롬프트까지 지워집니다. `LINE_MAX - 1` 검사는 버퍼 끝에 `'\0'` 을 넣을 자리를 남겨 둡니다.

## split: 한 줄을 단어로 나누기

`split` 은 `"mkdir docs"` 같은 문자열을 `argv[0] = "mkdir"`, `argv[1] = "docs"` 로 나눕니다. 흥미로운 점은 **문자열을 복사하지 않는다** 는 것입니다.
공백을 건너뛰다 단어의 첫 글자를 만나면 그 주소를 `argv` 에 담고, 단어 끝까지 간 뒤 그 자리의 공백을 `'\0'` 으로 바꿉니다. 그러면 원래 버퍼 안에 문자열 여러 개가 생기고, `argv` 는 그 시작점들을 가리키는 포인터 배열이 됩니다. 메모리 할당이 전혀 필요 없는 C다운 방법입니다.
`argc`, `argv` 라는 이름은 C의 `main(int argc, char **argv)` 에서 빌려 왔습니다. 진짜 운영체제에서는 셸이 이렇게 나눈 인자를 새 프로그램에 넘겨줍니다. 이 커널에서는 Step 23에서 `argv[0]` 을 디스크의 프로그램 이름으로 쓰게 됩니다.

## 명령 분기

`shell_run` 의 본체는 `argv[0]` 을 `strcmp` 로 비교하는 긴 `if-else` 사슬입니다. `help`, `clear`, `echo`, `pwd`, `ls`, `mkdir`, `touch`, `cd` 가 있고, 어디에도 해당하지 않으면 `unknown: xxx` 를 출력합니다.
단순하지만 이 구조는 끝까지 유지됩니다. Step 17에서 `cat`, `write` 같은 디스크 명령이 가지로 추가되고, Step 23에서는 마지막 `else` 가 "모르는 명령이면 디스크에서 같은 이름의 프로그램을 찾아 실행한다"로 바뀝니다. 이 마지막 가지 덕분에 커널을 고치지 않고도 명령을 늘릴 수 있게 됩니다.
`clear` 는 Step 01-4에서 미리 만들어 둔 `vga_clear()` 를 부릅니다.

## 메모리 위의 디렉터리 트리

```c
struct fs_node {
    char       name[32];
    fs_type_t  type;               /* FS_DIR / FS_FILE */
    fs_node_t *parent;
    fs_node_t *children[16];
    int        nchildren;
};
```

파일과 디렉터리는 모두 `fs_node` 하나로 표현합니다. 각 노드는 이름, 종류, 부모 포인터, 최대 16개의 자식 포인터를 가집니다. 노드는 Step 07의 `kmalloc` 으로 만듭니다. 힙이 없었다면 이런 트리는 만들 수 없었을 것입니다.
`fs_init()` 은 루트 노드 `/` 하나를 만들고, 현재 디렉터리 `cwd` 를 루트로 둡니다. 여기서 눈여겨볼 줄이 `root->parent = root;` 입니다. 루트의 부모를 루트 자신으로 해 두면, 루트에서 `cd ..` 을 해도 NULL을 따라가지 않고 그대로 루트에 머뭅니다. 특별한 경우를 코드 대신 데이터로 처리하는 요령입니다.

`fs_mkdir` 와 `fs_touch` 는 같은 이름이 이미 있는지 `fs_find` 로 확인하고, 자식 칸이 남아 있으면 새 노드를 만들어 붙입니다. `fs_cd` 는 `..` 이면 부모로, 아니면 이름으로 자식 디렉터리를 찾아 `cwd` 를 바꿉니다. `fs_pwd` 는 재귀 함수 `print_path` 로 `cwd` 에서 부모를 따라 루트까지 먼저 올라간 뒤, 돌아 내려오면서 이름을 찍어 `/docs/notes` 같은 경로를 만듭니다. 이렇게 하면 따로 버퍼에 모아 뒤집을 필요가 없습니다.
이 파일시스템에는 파일 **내용** 이 없습니다. `touch` 는 이름만 있는 빈 파일을 만들 뿐입니다. 그리고 모든 것이 힙에만 있어서 재부팅하면 사라집니다. 진짜 파일시스템은 Step 17에서 디스크 위의 ext2로 만나게 됩니다.

## 이 단계가 뒤에 남기는 것

셸은 이후 기능을 사람에게 보여 주는 창구가 됩니다. 새 기능이 생길 때마다 셸 명령으로 노출되고, 마지막에는 디스크의 프로그램을 실행하는 런처가 됩니다.
"readline → split → 명령 분기"의 구조는 Step 23까지 그대로 유지되며, 분기 끝의 `else` 가 확장의 자리입니다.
`fs_mkdir`, `fs_ls`, `fs_cd` 같은 함수 목록은 파일시스템이 제공해야 하는 연산의 첫 모델입니다. Step 17의 ext2는 같은 질문("이름으로 찾기, 목록 보기, 만들기")에 디스크 구조로 답합니다.

## 직접 만들어 보기

먼저 프롬프트를 띄우고 `readline` 으로 읽은 줄을 그대로 다시 출력하는 셸부터 만드세요. 백스페이스가 제대로 동작하는지 여기서 확인합니다.
다음으로 `split` 과 `help`, `echo`, `clear` 를 붙입니다. `echo a   b` 처럼 공백이 여러 개여도 `a b` 로 나오는지 시험해 보세요.
그다음 `fs_node` 와 루트를 만들고 `mkdir`, `ls` 를 구현한 뒤, `cd`(`..` 포함)와 `pwd` 를 붙입니다. 마지막으로 `main.c` 에서 셸을 프로세스로 등록합니다.
여유가 있다면 `cd /` 처럼 절대 경로를 받거나, `rmdir` 를 추가해 보세요. 노드를 지울 때 `kfree` 를 부르는 것도 잊지 마세요.

## 확인하기

부팅 후 `micro-os shell. 'help' for commands.` 와 `> ` 프롬프트가 나옵니다. 다음과 같이 입력해 보세요.

```
> mkdir docs
> cd docs
> pwd
/docs
> touch a.txt
> ls
> cd ..
> echo hello world
hello world
> foo
unknown: foo
```

`clear` 로 화면을 지울 수 있고, 백스페이스로 입력을 고칠 수 있어야 합니다.

## 막혔을 때

입력이 전혀 받아지지 않는다면 셸 프로세스가 스케줄되지 않았거나(`scheduler_add` 누락), 키보드 IRQ가 막힌 것입니다. 셸 시작 메시지가 나오는지부터 확인하세요.
백스페이스가 프롬프트까지 지운다면 `i > 0` 검사가 빠진 것입니다.
루트에서 `cd ..` 를 하자 페이지 폴트가 난다면 루트의 부모가 NULL로 남아 있는 것입니다. `fs_init` 에서 `root->parent = root` 를 확인하세요.
같은 이름의 디렉터리가 여러 개 생긴다면 `fs_find` 로 중복을 검사하지 않은 것입니다. 지금 코드는 `already exists` 로 막습니다.
셸이 가끔 이상하게 죽는다면 8KB 커널 스택을 의심하세요. `line[256]` 과 `argv[16]` 은 괜찮지만, 큰 지역 배열을 더 추가하면 스택이 넘칠 수 있습니다.
