# Step 13 — 부팅 로그 강화 (klog, TSC 타임스탬프, CPUID, 메모리 맵)

다음 단계에서 드디어 ring 3으로 내려갑니다. 그런데 그 전에 한 가지 문제를 해결해 두는 것이 좋습니다. 커널이 커질수록 로그도 늘어나는데, 지금은 모든 출력이 `printf` 하나로 화면과 시리얼에 똑같이 나갑니다.
유저 모드를 시작하면 "커널 입장에서 무슨 일이 일어났는가"를 보여 주는 디버그 메시지가 많이 필요해집니다. 시스템 콜이 불릴 때마다, 프로세스가 끝날 때마다 로그를 남기고 싶은데, 그걸 전부 화면에 찍으면 셸 화면이 금방 디버그 메시지로 뒤덮입니다. 게다가 언제 일어난 일인지 알 수 없으니 순서를 따지기도 어렵습니다.
이번 단계에서는 출력 함수를 용도별로 셋으로 나눕니다. 사용자에게 보여 줄 `printf`, 부팅 단계 기록용 `klog`, 시리얼에만 남기는 디버그용 `kprintf` 입니다. 그리고 시리얼 로그 앞에 부팅 후 경과 시간을 마이크로초 단위로 붙입니다. 덤으로 CPU 이름과 메모리 맵도 부팅 로그에 찍습니다.
이 단계는 원래 저장소의 커밋 `03c5032` 의 일부를 떼어 낸 것입니다.

바뀌는 파일이 많지만 대부분은 기존 `printf` 를 `klog` 로 바꾼 것입니다. 핵심은 `lib/printf.c`(재작성)와 `kernel/timer.c`(TSC)이고, 새 파일은 `kernel/cpuid.c`, `kernel/mmap.c` 입니다. `drivers/vga.c` 에는 하드웨어 커서 갱신이 추가됩니다.
`lib/printf.c` → `kernel/timer.c` → `kernel/cpuid.c` → `kernel/mmap.c` 순서로 읽으세요.

## 포맷 엔진과 출력 대상을 분리하기

Step 01-5에서 `printf` 의 모든 출력을 `emit()` 한 곳으로 모아 두었습니다. 그 덕분에 이번 재작성은 생각보다 간단합니다.
형식 문자열을 해석하는 부분을 `do_printf(emit_fn out, const char *fmt, va_list ap)` 라는 함수로 떼어 내고, 글자를 내보낼 함수를 인자로 받게 합니다.

```c
typedef void (*emit_fn)(char);

static void emit(char c)  { vga_putchar(c); serial_putchar(c); }  /* 화면 + 시리얼 */
static void semit(char c) { serial_putchar(c); }                  /* 시리얼만 */
```

이제 같은 포맷 엔진에 `emit` 을 주면 화면과 시리얼에, `semit` 을 주면 시리얼에만 출력됩니다. 숫자 변환 함수들(`do_uint`, `do_int`, `do_str`)도 모두 `emit_fn` 을 받도록 바뀝니다.
이렇게 "무엇을 출력할지"와 "어디로 출력할지"를 나누는 것은 C에서 함수 포인터를 쓰는 전형적인 예입니다. 나중에 로그를 메모리 버퍼에 남기고 싶다면 버퍼에 쓰는 `emit_fn` 하나만 추가하면 됩니다.
재작성하면서 `%02x` 처럼 폭을 지정해 0으로 채우는 형식도 지원하게 됐습니다. 바이트 값을 두 자리로 맞춰 찍을 때 쓰이고, Step 15의 PCI 장치 번호 출력이 이 형식을 씁니다.

## 출력 함수 세 가지

이렇게 만든 엔진 위에 세 함수가 올라갑니다.
`printf` 는 이전과 같습니다. 화면과 시리얼 양쪽에 나가고 타임스탬프가 없습니다. 셸의 출력처럼 사용자가 보라고 찍는 것에 씁니다.
`klog` 는 화면과 시리얼 양쪽에 나가되, 시리얼 쪽에만 앞에 `[    0.012345]` 같은 타임스탬프가 붙습니다. `[pmm]`, `[heap]`, `[tss]` 같은 부팅 단계 로그에 씁니다. 부팅하면서 화면에 진행 상황이 보이는 것이 좋고, 시리얼에는 시간까지 남는 것이 좋기 때문입니다.
`kprintf` 는 시리얼에만 나가고 타임스탬프가 붙습니다. 화면을 어지럽히면 안 되는 디버그 메시지용입니다. Step 14 이후의 `[syscall] pid N: exit(0)`, Step 21의 `[exec] ...`, Step 22의 `[wait] ...` 같은 메시지가 전부 `kprintf` 로 찍힙니다. 셸 화면은 깨끗하게 유지되고, 무슨 일이 있었는지는 터미널에서 시간 순서대로 볼 수 있습니다.
이 단계에서 기존 부팅 로그(`pmm.c`, `heap.c`, `vmm.c`, `tss.c`, `usermode.c` 등)의 `printf` 가 대부분 `klog` 로 바뀝니다. 바뀐 파일 수가 많은 이유가 이것입니다.

## TSC: CPU 클럭을 세는 시계

타임스탬프를 붙이려면 정밀한 시계가 필요합니다. Step 03의 PIT 타이머는 10ms마다 한 번씩만 울리니, 그보다 짧은 간격은 구분할 수 없습니다.
x86 CPU에는 **TSC(Time Stamp Counter)** 라는 64비트 카운터가 있습니다. CPU 클럭마다(최신 CPU에서는 일정한 기준 주파수마다) 1씩 올라가고, `rdtsc` 명령으로 언제든 읽을 수 있습니다. 3GHz CPU라면 1나노초보다 짧은 간격까지 구분할 수 있는 셈입니다.

```c
static inline uint64_t rdtsc(void) {
    uint32_t lo, hi;
    __asm__ volatile("rdtsc" : "=a"(lo), "=d"(hi));
    return ((uint64_t)hi << 32) | lo;
}
```

`rdtsc` 는 결과를 `edx:eax` 두 레지스터에 나눠 주므로 합쳐서 64비트 값을 만듭니다.
문제는 TSC가 1초에 얼마나 오르는지가 CPU마다 다르다는 것입니다. 그래서 **보정(calibration)** 이 필요합니다. 주기를 정확히 아는 시계, 즉 PIT와 비교해서 TSC의 속도를 재는 것입니다.

```c
void tsc_calibrate(void) {
    uint64_t t0 = ticks;
    while (ticks == t0) ;          /* 틱 경계를 기다린다 */
    uint64_t r0 = rdtsc();
    uint64_t t1 = ticks;
    while (ticks == t1) ;          /* 한 틱(10ms)을 더 기다린다 */
    uint64_t r1 = rdtsc();
    uint64_t tsc_per_tick = r1 - r0;
    tsc_per_us = tsc_per_tick / 10000;
    tsc_boot = r1 - (uint64_t)(t1 + 1) * tsc_per_tick;
}
```

먼저 틱이 바뀌는 순간을 기다려 출발선을 맞추고, 그때의 TSC를 읽습니다. 다시 한 틱이 지나기를 기다려 TSC를 읽으면, 두 값의 차이가 정확히 10ms 동안 TSC가 오른 양입니다. 이것을 10000으로 나누면 1마이크로초당 TSC 증가량이 나옵니다.
마지막 줄은 "틱 0, 즉 타이머를 켠 시점의 TSC 값"을 거꾸로 계산합니다. 지금까지 지난 틱 수에 틱당 TSC 증가량을 곱해 현재 값에서 빼는 것입니다. 이 값을 기준으로 삼으면 `tsc_elapsed_us()` 가 "타이머를 켠 뒤 몇 마이크로초가 지났는지"를 돌려줄 수 있습니다.
이 함수는 `ticks` 가 오르기를 기다리므로 **`sti` 이후에** 불러야 합니다. 인터럽트가 꺼져 있으면 `ticks` 가 영영 바뀌지 않아 무한 루프에 빠집니다. 보정 전에 `tsc_elapsed_us()` 를 부르면 `ticks × 10000` 으로 대충 계산한 값을 돌려줍니다.

## CPUID와 메모리 맵 로그

`cpuid` 명령은 CPU가 자기 자신에 대한 정보를 알려 주는 명령입니다. `eax` 에 질문 번호를 넣고 실행하면 `eax`, `ebx`, `ecx`, `edx` 에 답이 돌아옵니다.
`eax=0` 이면 제조사 문자열 12글자가 `ebx`, `edx`, `ecx` 순서로 4글자씩 담겨 옵니다(`GenuineIntel`, `AuthenticAMD`). 순서가 `ebx, ecx, edx` 가 아니라는 점이 함정입니다. `eax=0x80000002`~`0x80000004` 를 차례로 물으면 48글자짜리 CPU 이름이 16글자씩 옵니다. 이름 앞에 공백이 붙어 오는 CPU가 있어서 앞 공백을 지우고 출력합니다.
`kernel/mmap.c` 의 `mmap_log(info)` 는 Step 05에서 PMM이 읽었던 multiboot2 메모리 맵을 사람이 읽기 좋게 출력합니다. 태그를 도는 방법은 Step 05와 똑같고, 영역마다 `[mem]   [시작-끝] 종류 (크기)` 모양으로 한 줄씩 찍습니다. 주소는 `%08lx` 로 8자리를 맞춰 찍으므로 줄이 가지런히 정렬됩니다. PMM이 왜 그 값을 계산했는지 눈으로 확인할 수 있습니다.

## 하드웨어 커서

`drivers/vga.c` 에는 작은 개선이 하나 들어갑니다. VGA 텍스트 모드의 깜빡이는 밑줄 커서는 VGA 컨트롤러가 그리는데, 지금까지는 그 위치를 갱신하지 않아서 글자를 찍는 위치와 커서가 따로 놀았습니다.
VGA 컨트롤러의 인덱스 포트 `0x3D4` 에 레지스터 번호(`0x0F` 하위, `0x0E` 상위)를 쓰고 데이터 포트 `0x3D5` 에 커서 위치(행 × 80 + 열)의 상위·하위 바이트를 쓰면 커서가 그 칸으로 옮겨 갑니다. 글자를 찍을 때마다 이 일을 해 주면 셸에서 입력 위치에 커서가 깜빡입니다.

## 이 단계가 뒤에 남기는 것

출력 함수 세 가지의 구분이 이후 모든 코드의 습관이 됩니다. 사용자에게 보이는 것은 `printf`, 부팅 단계는 `klog`, 내부 디버그는 `kprintf` 입니다. 앞으로 화면에 안 보이는 메시지를 찾을 때는 시리얼 터미널을 보면 됩니다.
`do_printf(emit_fn, ...)` 구조는 출력 대상을 바꿔 끼우는 확장점이 됩니다. `tsc_elapsed_us()` 는 부팅 후 경과 시간을 재는 정밀한 시계로, 성능 측정이나 타임아웃 구현에 쓸 수 있습니다.
`kernel_main` 의 초기화 순서도 최종 모양에 가까워집니다. 출력 장치, `klog("[boot] micro-os starting...")`, CPUID, 인터럽트 계열, `sti`, TSC 보정, 메모리 맵, 메모리 관리 순서입니다.

## 직접 만들어 보기

먼저 기존 `printf` 를 `do_printf(emit_fn …)` 구조로 바꾸고, 출력이 이전과 똑같은지 확인하세요. 동작은 그대로이고 구조만 바뀌어야 합니다.
그다음 `semit` 과 `kprintf` 를 추가하고, 셸의 명령 처리 부분에 `kprintf("[shell] cmd=%s\n", argv[0])` 같은 줄을 넣어 화면에는 안 보이고 터미널에만 찍히는지 확인합니다.
`rdtsc` 와 보정을 넣을 때는 일부러 `sti` 전에 불러서 멈추는 것도 한번 보세요. 마지막으로 타임스탬프 출력과 `klog`, CPUID와 메모리 맵 로그를 붙입니다.

## 확인하기

QEMU를 띄운 터미널(시리얼)에 다음과 같이 시간이 붙은 부팅 로그가 나옵니다.

```
[   0.000000] [boot] micro-os starting...
[   0.000000] [cpu] GenuineIntel  QEMU Virtual CPU version ...
...
[   0.0xxxxx] [mem] BIOS memory map:
[   0.0xxxxx] [mem]   [00000000-0009fbff] usable (639 KB)
...
[   0.0xxxxx] [pmm] total: ...
```

화면에는 같은 로그가 타임스탬프 없이 나옵니다. 타이머를 켜기 전의 로그는 시간이 0으로 나오고, 보정이 끝난 뒤부터 마이크로초 단위 값이 나옵니다. CPU 이름은 QEMU 설정이나 호스트 CPU에 따라 다르게 나올 수 있습니다.
셸 화면에서 키를 누르면 입력 위치에 커서가 깜빡이는 것도 확인하세요.

## 막혔을 때

부팅이 `tsc_calibrate` 근처에서 멈춘다면 `sti` 전에 불렀거나, 타이머가 아직 초기화되지 않은 것입니다.
타임스탬프가 계속 0으로만 나온다면 보정 전의 로그이거나, 대체 계산(`ticks × 10000`)이 아직 0인 시점의 로그입니다. 보정 뒤의 로그를 보세요.
CPU 제조사 문자열이 `GenuntelineI` 처럼 섞여 나온다면 `edx` 와 `ecx` 의 순서를 바꾼 것입니다.
화면에 글자가 안 나오고 시리얼에만 나온다면 `klog` 가 `emit` 대신 `semit` 을 쓰고 있는지 확인하세요.
