# Step 01-2 — 32비트에서 화면에 직접 쓰기

앞 단계의 커널은 살아 있어도 그걸 알 방법이 QEMU 모니터밖에 없었습니다. 이번 단계에서는 화면 왼쪽 위에 `OK` 두 글자를 띄웁니다.
고작 두 글자지만 이게 생기면 디버깅 방식이 달라집니다. 앞으로 어셈블리 어딘가에서 문제가 생겼을 때 "`OK` 가 보이니 적어도 여기까지는 왔다"는 기준점이 생기기 때문입니다.
그리고 글자를 찍기 전에 꼭 해야 할 일이 하나 있습니다. GRUB이 레지스터에 넣어 준 두 값을 메모리로 옮겨 두는 일입니다. 이 두 값은 지금 바로 쓰지 않지만, 한 번 덮어쓰면 다시는 얻을 수 없습니다.

바뀌는 파일은 `boot/boot.s` 하나뿐입니다. 데이터 칸 두 개, 16KB 스택, 그리고 `_start` 에 몇 줄이 추가됩니다.

## GRUB이 넘겨주는 것: eax 와 ebx

GRUB이 `_start` 로 점프하는 순간, `eax` 에는 매직 값 `0x36D76289` 이, `ebx` 에는 **multiboot2 정보 구조체의 물리 주소** 가 들어 있습니다.
매직 값은 "multiboot2 규격을 따르는 부트로더가 너를 불렀다"는 증표입니다. 헤더의 매직(`0xE85250D6`)과는 다른 값이라는 점에 주의하세요. 헤더 매직은 커널이 부트로더에게, 이 값은 부트로더가 커널에게 보내는 신호입니다.
정보 구조체는 훨씬 중요합니다. 여기에는 "이 컴퓨터의 RAM이 어디서 어디까지 쓸 수 있는가"를 알려 주는 메모리 맵이 들어 있습니다. Step 05의 물리 메모리 관리자가 이걸 읽어서 빌려 줄 메모리를 정하고, Step 13의 부팅 로그도 이걸 출력합니다.

문제는 레지스터가 금방 덮인다는 점입니다. 다음 단계에서 페이지 테이블을 만들 때 `eax` 를 계산용으로 쓰고, `ebx` 도 언제든 쓰일 수 있습니다. 그래서 `_start` 의 거의 첫 줄에서 두 값을 메모리에 저장합니다.

```asm
.section .data
mb_magic: .long 0
mb_info:  .long 0
...
_start:
    cli
    mov %eax, mb_magic
    mov %ebx, mb_info
```

`.data` 섹션에 4바이트짜리 칸 두 개를 만들고 거기에 복사하는 것뿐입니다. 이 값들은 Step 01-3에서 64비트 C 함수 `kernel_main(magic, info)` 의 인자로 전달됩니다.

## 스택 만들기

GRUB은 스택을 마련해 주지 않습니다. `esp` 에 무슨 값이 들어 있는지 규격상 보장이 없으니, 함수를 부르거나 `push` 를 하는 순간 아무 메모리나 덮어쓸 수 있습니다.
그래서 우리 스택을 직접 만듭니다.

```asm
.section .bss
.align 16
stack_bottom: .skip 16384      /* 16KB 커널 스택 */
stack_top:
...
    mov $stack_top, %esp
    xor %ebp, %ebp
```

`.bss` 섹션에 16KB를 비워 두고, `esp` 를 그 **끝** 인 `stack_top` 에 맞춥니다. x86의 스택은 높은 주소에서 낮은 주소로 자라기 때문에, 시작점은 영역의 맨 위여야 합니다.
`.bss` 는 파일에 실제 바이트로 들어가지 않고 "이만큼을 0으로 채워 달라"는 크기 정보만 들어가므로, 16KB를 잡아도 커널 파일이 커지지 않습니다. GRUB이 ELF를 로드하면서 이 영역을 0으로 채워 줍니다.
`ebp` 를 0으로 만드는 것은 디버거가 스택 프레임을 거슬러 올라갈 때 "여기가 맨 바닥"이라는 표시가 됩니다.
이 스택은 Step 01-3에서 64비트로 넘어간 뒤에도 그대로 쓰이고, Step 08에서 프로세스가 생기기 전까지 커널의 유일한 스택입니다.

## VGA 텍스트 버퍼에 직접 쓰기

PC는 부팅 직후 **VGA 텍스트 모드** 로 화면을 보여 줍니다. 가로 80칸, 세로 25줄의 글자 격자이고, 이 격자의 내용이 물리 주소 `0xB8000` 부터 메모리처럼 보입니다.
칸 하나는 2바이트입니다. 낮은 바이트가 글자(ASCII), 높은 바이트가 색입니다. 색 바이트는 다시 위 4비트가 배경색, 아래 4비트가 글자색입니다.
그래서 어떤 칸에 글자를 띄우려면 그냥 그 메모리에 2바이트를 쓰면 됩니다. 드라이버도 함수도 필요 없습니다.

```asm
    movl $0x2F4B2F4F, 0xB8000
```

한 번에 4바이트, 즉 칸 두 개를 씁니다. x86은 리틀 엔디언이라 메모리에는 `4F 2F 4B 2F` 순서로 들어갑니다. 첫 칸은 글자 `0x4F`('O')와 색 `0x2F`, 둘째 칸은 글자 `0x4B`('K')와 색 `0x2F` 입니다. `0x2F` 는 배경 2(초록), 글자 F(밝은 흰색)이니 초록 바탕에 흰 글씨 `OK` 가 됩니다.
지금은 페이징이 꺼져 있으므로 주소 `0xB8000` 이 그대로 물리 주소입니다. Step 01-3에서 페이징을 켠 뒤에도 0~1GB를 "가상 주소 = 물리 주소"로 매핑하기 때문에, 이 주소는 앞으로도 계속 같은 의미로 쓰입니다.

## 이 단계가 뒤에 남기는 것

GRUB이 준 두 값은 `mb_magic`, `mb_info` 에 안전하게 보관됩니다. 커널에는 16KB짜리 스택이 하나 생겼습니다. 그리고 "화면 = `0xB8000` 의 2바이트 칸들"이라는 사실을 알게 됐는데, 이게 Step 01-4의 VGA 드라이버가 하는 일의 전부이고, Step 04의 마우스 커서가 칸의 색 바이트만 바꾸는 방식으로 그려지는 근거이기도 합니다.

## 직접 만들어 보기

앞 단계의 `boot.s` 에서 출발해 `movl` 한 줄부터 넣어 보세요. 화면에 `OK` 가 나오면 성공입니다.
그다음 색 바이트를 바꿔 보거나, `0xB8000 + 160` 에 써서 두 번째 줄에 글자가 나오는 것을 확인해 보세요. 한 줄이 80칸 × 2바이트 = 160바이트라는 걸 몸으로 익히게 됩니다.
마지막으로 `mb_magic`, `mb_info` 저장과 스택 설정을 넣습니다. 이것들은 화면에 아무 변화를 주지 않으니, QEMU 모니터에서 `info registers` 로 `ESP` 가 `stack_top` 근처인지 확인해 보면 됩니다.
조금 더 나아가고 싶다면 `eax` 가 `0x36D76289` 일 때만 `OK` 를 찍도록 `cmp` 와 `jne` 로 분기를 넣어 보세요. 다음 단계에서 같은 검사를 C로 다시 하게 됩니다.

## 확인하기

GRUB 메뉴 뒤에 검은 화면이 나오고, 왼쪽 위에 초록 바탕의 `OK` 가 보이면 됩니다. 커널은 그 상태로 멈춰 있습니다.
화면에 GRUB이 남긴 글자가 일부 남아 있을 수 있는데, 아직 화면을 지우는 코드가 없어서 그렇습니다. Step 01-4의 `vga_init` 이 화면을 깨끗이 지웁니다.

## 막혔을 때

`OK` 가 보이지 않고 재부팅이 반복된다면, 명령 자체보다 그 앞에서 CPU가 죽은 경우가 많습니다. 이 단계에서는 거의 없지만, `_start` 앞에 다른 섹션이 끼어들어 엉뚱한 곳으로 점프했을 가능성이 있으니 `objdump -d` 로 `_start` 위치를 확인하세요.
글자가 엉뚱하게 나온다면 바이트 순서를 다시 보세요. `0x4F2F4B2F` 처럼 쓰면 글자와 색이 뒤바뀝니다.
`objdump -d` 로 확인했을 때 `_start` 코드가 이상하게 해석되어 보이는 건 정상입니다. objdump가 64비트 코드로 가정하고 디스어셈블하기 때문이고, `objdump -d -M i386` 을 쓰면 제대로 보입니다.
