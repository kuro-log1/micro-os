# Step 03 — PIC 리매핑 & PIT 타이머 (IRQ0)

앞 단계에서는 CPU가 스스로 일으키는 예외를 받았습니다. 이번에는 CPU **바깥** 에서 오는 신호를 받습니다.
키보드를 누르거나, 디스크가 읽기를 마치거나, 타이머가 정해진 시간이 됐을 때 장치는 CPU에 "나 좀 봐 줘"라는 신호를 보냅니다. 이것이 하드웨어 인터럽트, 줄여서 **IRQ** 입니다.
이번 단계에서는 IRQ를 C 함수로 받는 틀을 만들고, 그 첫 사용자로 1초에 100번 울리는 타이머를 붙입니다. 화면에는 1초마다 `[timer] N s` 가 찍힙니다.
지금은 시간을 세는 게 전부지만, 이 타이머는 Step 08에서 **스케줄러를 깨우는 심장 박동** 이 됩니다. 프로그램이 스스로 CPU를 양보하지 않아도 커널이 강제로 다른 프로그램으로 넘어갈 수 있는 근거가 바로 이 타이머입니다.

새 파일은 `kernel/pic.c`·`pic.h` 와 `kernel/timer.c`·`timer.h` 입니다. `kernel/idt_asm.s` 에 IRQ 스텁이, `kernel/idt.c` 에 IRQ 디스패처가 추가되고, `kernel/main.c` 가 초기화를 부른 뒤 인터럽트를 켭니다.
`pic.c` → `idt_asm.s`(IRQ_STUB) → `idt.c`(irq_handler) → `timer.c` 순서로 읽으세요.

## PIC: 장치 신호를 모아 CPU에 전달하는 칩

PC에는 장치들의 인터럽트 선을 모아서 CPU에 전달하는 **8259 PIC(Programmable Interrupt Controller)** 가 두 개 있습니다. 각각 8개의 입력을 받는데, 두 번째(슬레이브) PIC의 출력이 첫 번째(마스터) PIC의 2번 입력에 연결되어 있어서 전체적으로 IRQ 0~15, 16개의 선을 다룹니다.
IRQ 0이 타이머, 1이 키보드, 12가 PS/2 마우스, 14가 첫 번째 IDE 디스크인 식으로 번호가 정해져 있습니다.

장치가 신호를 보내면 PIC는 그 IRQ 번호에 **오프셋** 을 더한 인터럽트 번호로 CPU를 부릅니다. 문제는 전원을 켰을 때의 기본 오프셋입니다. 마스터 PIC는 IRQ 0~7을 인터럽트 8~15번으로 보내도록 되어 있는데, 이 번호들은 Step 02에서 본 것처럼 CPU 예외 자리입니다. 8번은 Double Fault, 13번은 General Protection입니다.
이대로 인터럽트를 켜면, 타이머가 처음 울리는 순간 커널은 Double Fault가 났다고 착각하고 패닉에 빠집니다.
이것은 오래된 PC 설계의 유명한 실수이고, 모든 x86 커널은 맨 처음 PIC의 오프셋을 옮기는 **리매핑** 을 합니다.

`pic_init()` 은 네 개의 초기화 명령어(ICW1~4)를 정해진 순서로 보냅니다.
ICW1(`0x11`)은 "지금부터 초기화를 시작한다, ICW4까지 보내겠다"는 신호입니다. ICW2는 새 오프셋으로, 마스터에 `0x20`(32), 슬레이브에 `0x28`(40)을 줍니다. 이제 IRQ 0~7은 인터럽트 32~39번, IRQ 8~15는 40~47번으로 들어옵니다.
ICW3은 두 칩의 연결 방식을 알려 줍니다. 마스터에게는 "2번 입력에 슬레이브가 있다"(`0x04`, 비트 2), 슬레이브에게는 "너는 마스터의 2번에 물려 있다"(`0x02`, 번호 2)를 보냅니다. ICW4(`0x01`)는 8086 모드로 동작하라는 뜻입니다.
마지막으로 데이터 포트에 0을 써서 모든 IRQ의 마스크를 풉니다. 명령 사이사이의 `io_wait()` 은 오래된 PIC가 명령을 처리할 틈을 주는 짧은 지연입니다.

## EOI: "다 처리했어"라고 알려 주기

PIC는 한 IRQ를 CPU에 전달한 뒤, CPU가 **EOI(End Of Interrupt)** 명령을 보내기 전까지는 그 IRQ나 그보다 우선순위가 낮은 IRQ를 다시 보내지 않습니다. EOI를 잊으면 타이머가 딱 한 번만 울리고 영영 조용해집니다.
`pic_send_eoi(irq)` 는 마스터의 명령 포트(`0x20`)에 `0x20` 을 씁니다. IRQ 8 이상이면 슬레이브에도 보내야 합니다. 슬레이브의 인터럽트는 마스터를 거쳐 왔기 때문에 두 칩 모두 "처리 중" 상태로 기다리고 있기 때문입니다.

## IRQ 스텁과 디스패처

IRQ를 받는 경로는 Step 02의 예외 경로와 거의 같습니다. `IRQ_STUB` 매크로로 `irq0` ~ `irq15` 스텁 16개를 만들고, 각 스텁은 가짜 에러 코드 0과 인터럽트 번호(32~47)를 쌓은 뒤 공통 루틴 `irq_common` 으로 점프합니다. `irq_common` 은 `isr_common` 과 똑같이 레지스터를 저장하고 `registers_t*` 를 넘기는데, 부르는 C 함수만 `irq_handler` 입니다.
하드웨어 인터럽트는 에러 코드를 쌓지 않으니 모든 스텁이 가짜 0을 쌓습니다. 덕분에 `registers_t` 를 그대로 쓸 수 있습니다.

C 쪽의 디스패처는 몇 줄뿐입니다.

```c
void irq_handler(registers_t *r) {
    int irq = (int)r->int_no - 32;
    pic_send_eoi(irq);
    if (irq_table[irq])
        irq_table[irq](r);
}
```

인터럽트 번호에서 32를 빼서 IRQ 번호를 구하고, EOI를 보낸 뒤, 그 IRQ에 등록된 함수가 있으면 부릅니다.
드라이버는 `irq_install_handler(irq, fn)` 으로 `irq_table` 에 자기 함수를 등록합니다. 디스패처는 장치에 대해 아무것도 모르고, 장치는 IDT나 PIC에 대해 아무것도 몰라도 됩니다. Step 04의 키보드와 마우스, 그리고 이번 단계의 타이머가 모두 이 한 줄짜리 등록으로 붙습니다.

여기서 **EOI를 핸들러를 부르기 전에 보낸다** 는 점을 꼭 기억해 두세요. 지금은 순서가 어느 쪽이든 상관없어 보입니다. 하지만 Step 08에서 타이머 핸들러 안에서 다른 프로세스로 전환하게 되면, 핸들러는 그 프로세스가 다시 선택될 때까지 한참 동안 끝나지 않습니다. EOI가 핸들러 뒤에 있다면 그동안 PIC는 타이머 인터럽트를 보내지 않고, 시스템 전체가 멈춥니다. 지금 이 순서로 짜 두는 것이 미래의 버그를 막습니다.
`irq_init()` 은 IDT의 32~47번 칸에 16개 스텁을 모두 등록합니다. 핸들러가 없는 IRQ라도 게이트는 채워 둬야 합니다. 빈 게이트로 인터럽트가 들어오면 그 자체가 예외가 되기 때문입니다.

## PIT: 일정한 간격으로 울리는 타이머

**PIT(Programmable Interval Timer, 8253/8254)** 는 1,193,182Hz로 똑딱이는 카운터입니다. 카운터에 어떤 값(분주값)을 넣어 두면, 그 값만큼 셀 때마다 IRQ 0을 한 번 일으킵니다. 그래서 1초에 `hz` 번 울리게 하려면 분주값을 `1193182 / hz` 로 하면 됩니다. 100Hz면 11931, 즉 약 10ms마다 한 번입니다.

```c
uint32_t divisor = 1193182 / hz;
outb(0x43, 0x36);                       /* 채널 0, 하위/상위 바이트 순서, 모드 3 */
outb(0x40, (uint8_t)(divisor & 0xFF));
outb(0x40, (uint8_t)(divisor >> 8));
```

포트 `0x43` 은 PIT의 명령 포트이고 `0x40` 은 채널 0의 데이터 포트입니다. 명령 `0x36` 은 "채널 0을, 분주값은 하위 바이트부터 두 번에 나눠 받고, 모드 3(사각파)으로 동작하라"는 뜻입니다.
타이머 핸들러는 `ticks` 를 하나 늘리고, 100번마다 경과한 초를 출력합니다. `ticks` 를 `volatile` 로 둔 것은 인터럽트 핸들러가 바꾸는 값을 다른 코드가 읽을 때 컴파일러가 옛 값을 레지스터에 붙잡아 두지 않게 하려는 것입니다.
`timer_ticks()` 는 이 값을 다른 파일에 공개하는 함수입니다. 같은 파일 안에서는 Step 13의 TSC 보정이 이 `ticks` 가 바뀌는 순간을 기다리는 방식으로 시간을 잽니다.

## 인터럽트 켜기

`kernel_main` 의 초기화 순서는 이렇게 됩니다.

```c
idt_init();
pic_init();
irq_init();
timer_init(100);
__asm__ volatile("sti");

for (;;) __asm__ volatile("sti; hlt");
```

예외를 받을 IDT, IRQ를 32번 이후로 옮긴 PIC, IRQ 게이트, 타이머 핸들러가 전부 준비된 **다음에야** `sti` 로 인터럽트 플래그를 켭니다. 하나라도 빠진 상태에서 켜면 첫 타이머 신호가 엉뚱한 곳으로 가서 바로 문제가 납니다.
메인 루프의 `hlt` 는 이제 의미가 바뀝니다. Step 01에서는 영원히 자는 명령이었지만, 이제는 "다음 인터럽트가 올 때까지 잠깐 잔다"가 됩니다. 타이머가 울리면 깨어나 핸들러를 돌고, 루프로 돌아와 다시 잡니다. 할 일이 없을 때 CPU를 바쁘게 돌리지 않는, 운영체제의 기본 자세입니다.

## 이 단계가 뒤에 남기는 것

인터럽트 번호의 배치가 확정됐습니다. 0~31은 CPU 예외, 32~47은 IRQ 0~15이고, 남은 자리 중 0x80번이 Step 11에서 시스템 콜이 됩니다.
`irq_install_handler(irq, fn)` 은 모든 장치 드라이버가 인터럽트를 받는 표준 방법이 됩니다. "EOI를 먼저 보내고 핸들러를 부른다"는 순서는 Step 08의 선점형 스케줄링을 가능하게 합니다.
그리고 `timer_handler` 는 앞으로 내용이 바뀌는 자리입니다. Step 04에서는 출력이 사라지고, Step 08에서는 10틱마다 `schedule()` 을 부르게 됩니다.

## 직접 만들어 보기

`pic_init` 부터 만들되, 처음에는 리매핑 없이 `sti` 만 해 보세요. 곧바로 Double Fault 패닉이 나는 것을 볼 수 있습니다. 리매핑이 왜 필요한지 눈으로 확인하는 가장 좋은 방법입니다.
그다음 리매핑을 넣고, IRQ 스텁을 예외 스텁과 같은 모양으로 만듭니다. `irq_handler` 에서는 처음에 IRQ 번호만 출력해 보세요. 타이머를 설정하지 않아도 PIT는 기본 주파수(약 18.2Hz)로 이미 돌고 있어서 `0` 이 계속 찍힐 것입니다.
EOI를 빼고 돌려서 딱 한 번만 찍히는 것도 확인해 보세요. 마지막으로 PIT를 100Hz로 설정하고 초 단위 출력을 붙입니다.

## 확인하기

부팅 메시지 뒤로 `[timer] 1 s`, `[timer] 2 s`, … 가 실제 시계와 비슷한 속도로 화면과 터미널에 찍힙니다.

## 막혔을 때

`sti` 직후 Double Fault나 General Protection 패닉이 난다면 리매핑이 되지 않은 것입니다. ICW2에 준 오프셋을 확인하세요.
첫 틱만 오고 멈춘다면 EOI를 보내지 않았거나, 마스터의 명령 포트가 아닌 데이터 포트에 보낸 것입니다.
타이머는 되는데 다른 IRQ가 들어올 때 패닉이 난다면 `irq_init` 이 16개 게이트를 모두 채우는지 확인하세요.
출력 속도가 너무 빠르거나 느리다면 분주값 계산이나 PIT 명령 바이트를 다시 보세요. 하위 바이트와 상위 바이트를 거꾸로 보내는 실수가 흔합니다.
